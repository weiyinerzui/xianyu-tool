# 闲鱼店铺运营工具 · 项目分析与开发计划

> 分析日期：2026-10-05
> 分析对象：6 个参考仓库 + 工作区已有 `xianyu-ops` v0.3.0
> 结论：**不新建项目，改造已有的 `xianyu-ops`**。核心引擎（违禁词/标题/诊断/评分）已实测可用，
> 唯一致命缺口是**数据源**——闲鱼已上登录墙，导致选品功能实际不可用。

---

## 一、参考仓库横向分析

| 仓库 | 定位 | 技术 | 可复用资产 | 判断 |
|---|---|---|---|---|
| **goofish-cli** | PyPI 官方 CLI+MCP，17 命令 | Python, execjs 签名, WebSocket | ⭐⭐⭐⭐⭐ **最大金矿**：签名算法、风控熔断、浏览器 cookie 自动导入、5 个 Skills 知识库（2382 行） | **必须集成**，作为数据层底座 |
| **xianyu-tool** | 同作者选品工具（12 类目爆款榜） | FastAPI + React + Playwright | 热度公式 `want_count / days_since_publish`、CSV 导出、一键复刻 | 借鉴选品逻辑 |
| **goofish_api** | 最小签名示例 | requests + hashlib | `mtop.taobao.idlemtopsearch.pc.search`、sign=md5(token&t&appKey&data) | 已被现有项目吸收 |
| **XianYuApis** | 签名 JS + WS 协议 | execjs + node | `gen_tfstk.js` / `et_f.js`、token 引导逻辑 | 备选签名方案 |
| **ai-goofish-monitor** | 监控告警 | Docker + Tailwind | 长驻会话管理、失败守卫 | 参考调度稳定性 |
| **xianyu_spider** | 8KB 最小爬虫 | requests | 无 | 无复用价值 |

**关键洞察**：`xianyu-ops` 已有代码的注释大量写着"参考 goofish-cli"，但**它只是复刻了设计思想，
从未真正集成这个 PyPI 包**。这是最大的架构浪费。

| 标题评分 | ✅ 实测 72.5 分，输出 5 段式缺失诊断 + 5 条改写建议 |
| 曝光诊断 | ✅ 实测概率归因（标题没SEO优化 20%），输出修复动作 |

实测输出示例（违禁词）：
```
输入："全网最低价，100%正品，保证永久有效，加微信详聊"
结果：passed=false, risk_level=danger, hit_count=6
命中：全网最低[0,4]→同类市价偏低 / 最[2,3]→较 / 100%[6,10] / 永久[15,17]→长期 / 微信[21,23]
```

### ❌ 致命缺口：数据源已死

这是本次分析**最重要的发现**，也是整个计划的重心：

```
L1 httpx 直签 API  → 风控触发 RGV587_ERROR "哎哟喂,被挤爆啦"  → 0 条
L2 Playwright 无痕 → 页面渲染出「登录后可以更懂你，推荐你喜欢的商品！」
                      搜索结果卡片数 = 0，mtop API 仅返回静态资源
```

**闲鱼已对搜索结果强制登录墙**。这不是代码 bug，是平台策略变更。

验证证据链：
1. 现有 `httpx_crawler.py` 直签 API → 被风控拦截
2. 官方 `goofish-cli search items` → 同样报 `AuthRequiredError`
3. 官方 `goofish-cli` 甚至内置了 `browser_cookie.py`（262 行）自动从
   Chrome/Edge/Firefox 提取闲鱼登录态 —— 官方自己就承认搜索必须登录

**结论：选品功能的唯一可行路径 = 集成 goofish-cli 的登录态管理。**
现有 `session_manager.py`（179 行自研实现）需被替换。

## 三、需求对照与缺口分析

| 你的需求 | 现状 | 缺口 |
|---|---|---|
| 选品：筛出高销量有需求商品 | 🟡 评分引擎完整，但**抓不到数据** | 🔴 P0：接 goofish-cli 登录态；想要数历史快照（算增速） |
| 违禁词检测 | 🟢 已实测可用 | 🟡 需补虚拟商品专属规则 + 上下文误报消解 |
| 提升曝光量技巧 | 🟢 诊断+标题优化可用 | 🟡 缺"自己的商品"真实曝光数据回流 |
| 曝光不稳定 | 🟡 有诊断规则引擎 | 🔴 P0：无自己商品的曝光/浏览时间序列数据 |
| 不知道是否畅销 | 🟡 有在售商品列表 API 缺口 | 🔴 P0：接 `goofish item list` 拉自己商品 |

### 建议补充的功能（超出你原始需求）

1. **爆品复制雷达** — 监控关键词下 Top 商品，发现新品/涨价，用 goofish-cli 一键"复刻商品信息"
2. **关键词机会挖掘** — 找出"有搜索量但供给少"的长尾词（真正的选品金矿）
3. **商品健康度巡检** — 定时扫描自己所有在售商品，标记触犯新规/标题过时/长期零曝光
4. **一键发布前检查** — 标题+描述+图片走完整 pre-publish checklist 再上架

## 四、技术选型

### 架构决策：分层数据源

```
┌─────────────────────────────────────────────┐
│  xianyu-ops (FastAPI + React)               │  ← 现有，保留
│  选品 / 违禁词 / 诊断 / 看板 / AI            │
└──────────────┬──────────────────────────────┘
               │ subprocess / HTTP
┌──────────────▼──────────────────────────────┐
│  goofish-cli (PyPI 0.4.0, 新增依赖)         │  ← 新增，底座
│  auth login --qr / search items             │
│  item list / item get / item publish        │
│  内置风控熔断 + 令牌桶限流                   │
└──────────────┬──────────────────────────────┘
               │ 登录 cookie（QR / 浏览器自动导入）
┌──────────────▼──────────────────────────────┐
│  闲鱼 goofish.com                            │
└─────────────────────────────────────────────┘
```

**为什么不用现有自研爬虫**：已实测双双失效，且 goofish-cli 是官方维护、随平台更新、
还带限流熔断。自己维护签名等于跟平台对抗，注定被超越。

### 关键技术决策

| 项 | 决策 | 理由 |
|---|---|---|
| 数据层 | **subprocess 调 goofish-cli** | 不 fork 源码，升级跟版；JSON 输出易解析 |
| 登录态 | `goofish auth login --qr` 优先，浏览器自动导入兜底 | 用户零操作扫码即可 |
| 签名/风控 | 全部委托 CLI | 平台变更时只需升级 pip 包 |
| 想要数增速 | 商品快照表 + 定时 diff | 现有 scorer 已算好公式，只缺数据 |
| 虚拟商品合规 | 扩展 `banned_words.yaml` 的 `virtual_goods` 类 | 你的类目，通用词库覆盖不足 |

## 五、开发计划（4 阶段）

### Phase 1 · P0 · 数据源打通（预计 1-2 天）
> 目标：让选品功能真正能用

1. `backend/requirements.txt` 加 `goofish-cli==0.4.0`
2. 新建 `app/services/goofish_adapter.py`
   - `search_items(keyword, pages)` → 调 `goofish search items`
   - `list_my_items()` → 调 `goofish item list`
   - `get_item(id)` → 调 `goofish item get`
   - 统一超时/JSON 解析/`AuthRequiredError` 捕获
3. 新建 `app/api/goofish_auth.py` 路由组
   - `POST /api/v1/goofish/auth/qr` → 生成扫码登录链接
   - `GET /api/v1/goofish/auth/status` → 登录态有效性
   - `GET /api/v1/goofish/auth/qr-image` → 二维码图片
4. 改造 `session_manager.py`：**废弃自研实现**，改为代理 CLI
5. 前端 Settings 页增加登录态面板（扫码 + 状态灯 + 风控熔断解除）
6. **验收标准**：真实账号扫码后，前端点"一键爬取"能返回 >0 条商品

### Phase 2 · P0 · 商品数据资产化（预计 2-3 天）
> 目标：解决"不知道是否畅销"和"曝光不稳定"

1. 新增 ORM 模型 `MyItem`（自己商品）与 `ItemSnapshot`（快照）
   - MyItem: item_id / title / price / status / publish_time / 类目
   - ItemSnapshot: item_id / snapshot_at / want_count / view_count / price
2. 定时任务（APScheduler，每 6h）
   - 拉取 `item list` → 写入/更新 MyItem
   - 对每个在售商品抓详情 → 写 ItemSnapshot
   - diff 快照算出 **想要数增速 / 浏览增速 / 价格变动**
3. 新增服务 `demand_analyzer.py`
   - 判定"畅销/滞销"：7 日想要数增速 + 浏览增速双阈值
   - 判定"曝光异常"：浏览量 3 日均值跌幅 >50% → 告警
4. 新增 API + 前端页面「我的商品健康度」
   - 每商品一行：想要数趋势曲线、曝光趋势、状态标签（爆款/平稳/滞销/异常）
   - 滞销商品一键给出改价/改标题/下架建议
5. **验收标准**：能对一个真实账号跑出 ≥3 天趋势数据并正确标出滞销品

### Phase 3 · P1 · 选品增强（预计 2 天）
> 目标：从"能抓"升级到"会选品"

1. 关键词机会挖掘（供需差模型）
   - 跑一批种子关键词 → 统计各词下商品数、均价、想要数分布
   - 计算「需求热度 / 供给密度」比值，输出**蓝海词榜**
2. 爆品复制雷达
   - 监控 Top 50 商品，diff 出新品、调价、下架
   - 复用 `xianyu-tool` 的 CSV 导出 + 商品信息一键复刻
3. 扩展 `banned_words.yaml` 的 `virtual_goods` 类
   - 补：网盘/链接/加V/送资料/内部资料/原价298 等虚拟商品专属红线
4. 违禁词上下文消歧
   - 当前"最"是单字，极易误报（如"最新最全资料"）
   - 增加上下文窗口判定 + 白名单机制
5. **验收标准**：蓝海词榜能输出 ≥10 个可操作关键词；误报率显著下降

### Phase 4 · P1 · 曝光提升闭环（预计 1-2 天）
> 目标：把"提升曝光技巧"变成可执行的自动化

1. 曝光诊断接入真实数据
   - 现在诊断靠手工填数字 → 改为自动读取 MyItem 快照
2. 定时商品巡检 + 告警
   - 扫描自己全部在售商品，标记触犯新规/标题过时/长期零曝光
3. AI 文案助手升级（已有 `llm_advisor.py`）
   - 输入关键词 + 目标人群 → 生成标题候选 + 描述 + 图片文案
4. 一键发布前 checklist
   - 标题/描述/图片/价格 四维检查，全过才允许上架
5. **验收标准**：跑一次真实巡检，能输出带优先级的行动清单

## 六、风险与合规

| 风险 | 等级 | 对策 |
|---|---|---|
| 账号风控/封号 | 🔴 高 | 只读为主，不做批量写操作；复用 CLI 内置令牌桶（1写/分钟）+ 熔断器 |
| 登录态过期 | 🟡 中 | 状态灯提示 + 一键重新扫码 |
| 平台 API 变更 | 🟡 中 | 用 CLI 而非自研签名，升级 pip 即可 |
| 虚拟商品合规风险 | 🔴 高 | 违禁词库持续维护；明确不做"引流到微信"类话术 |
| 数据准确性 | 🟢 低 | 快照 diff 而非单点值，避免噪声误判 |

> ⚠️ **重要提醒**：闲鱼对虚拟商品的"免费软件/学习资料"类目有专门规则，
> 涉及"引流站外""共享账号""盗版资源"是封号红线。本工具应定位为
> **合规运营辅助**，不提供绕过平台规则的能力。

## 七、立即可做（今天就能用）

无需任何开发，现有 v0.3.0 已经能直接解决你**一半**的问题：

```bash
cd xianyu-ops/backend
.venv/bin/uvicorn app.main:app --port 8000
# 另开终端
cd xianyu-ops/frontend && npx vite
```

打开 http://localhost:5173，可用功能：
- **违禁词检测** — 发布前必过，实测准确
- **标题优化** — 5 段式评分改写
- **曝光诊断** — 流量掉了先查这里
- **AI 助手** — 配 `XIANYU_OPS_LLM_API_KEY` 后启用

选品功能需等 Phase 1 完成后才可用。
